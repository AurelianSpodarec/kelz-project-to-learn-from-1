# Organisation Administration

The `OrganisationAdmin` component allows the logged-in user to view organisations, edit them, delete them, or add new organisations to the platform.

## Usage

Implementing this component is more complicated than usual because there are three components that must be defined and implemented separately in order for it to work. This is because different contexts for `OrganisationAdmin` have different visual design guidelines that must be worked around. Developers therefore need more control over how these components are implemented.

There are three main parts to this component:

1. `OrganisationAdmin`
2. `OrganisationsPanel`
3. `OrganisationsProvider`

`OrganisationAdmin` contains the `Table` component for displaying the index organisations data as well as several tools for sorting and refining the Index Organisations query.

`OrganisationsPanel` is a `FlyOutPanel` component that contains the View Organisation and Edit Organisation functionality. Because `FlyOutPanel` is an absolutely positioned element, it must be defined at the root of the page being designed. It is for this reason that a React context is desirable for managing the state of this component.

`OrganisationsProvider` is the Context Provider. It controls the state of the `OrganisationAdmin` component and the `OrganisationsPanel` component.

Although the particular state management technique within the context is left open, it makes sense to use a `useReducer` hook for state management of page actions.

An example of a functional `OrganisationsProvider` instance can be found inside `./story/organisations.story.provider.js`. Refer to this when considering the bare minimum of fields required to make this component functional.

Implement as follows:

```javascript
<>
  <Container>
    <OrganisationAdmin {...props} />
  </Container>
  <OrganisationsPanel {...props} />
</>
```
